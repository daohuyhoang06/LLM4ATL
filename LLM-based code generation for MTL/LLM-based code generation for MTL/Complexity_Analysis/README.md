# Complexity Analysis Output

Generated by running the three-script pipeline in `scripts/` on the 47 reference transformation scripts.

## Files

| File | Description |
|------|-------------|
| `complexity_features.csv` | Per-script complexity metrics for all 47 reference scripts |
| `correlation_results.csv` | Spearman ρ between complexity features and quality metrics |
| `scatter_complexity_vs_quality.pdf` | Scatter plots: complexity vs. Pass@1 / ChrF per LLM × strategy |
| `table1_extended.tex` | LaTeX table of complexity aggregated by MTL (min/med/max/mean) |

## Complexity Metric Definitions

### LoC (Lines of Code)
Non-empty, non-comment lines. Comments stripped using language-specific conventions:
- ATL: `--` prefix
- ETL / QVTo / Reactions: `//` prefix

### n_rules — Number of Transformation Rules

| MTL | What is counted | Keyword(s) |
|-----|----------------|------------|
| ATL | Matched rules and lazy rules | `rule`, `lazy rule` |
| Reactions | Reaction blocks (event-triggered transformation units) | `reaction` |
| ETL | Rule definitions | `rule` |
| QVTo | Mapping blocks + constructor blocks + main entry point | `mapping`, `constructor`, `main()` |

### n_helpers — Number of Modular Helper Units

| MTL | What is counted | Keyword |
|-----|----------------|---------|
| ATL | Helper functions (`helper def:` and `helper context ... def:`) | `helper` |
| Reactions | Routine definitions (transformation sub-procedures with match/update blocks) | `routine` |
| ETL | Operation definitions (utility functions) | `operation` |
| QVTo | No helper-level constructs present in the 10 reference scripts | — (0) |

> Note: "helper" is used as a shorthand for language-equivalent modular units. ATL helpers and ETL operations are pure utility functions; Reactions routines are transformation sub-procedures that contain match/update logic and are called from reactions.

### mccabe — McCabe-style Cyclomatic Complexity

Computed per rule/helper/routine/mapping body as:

```
mccabe_body = 1 + count(if, else if, while, for, switch, case, default)
```

For Reactions, `with` guard clauses are also counted. The total per script is the sum over all bodies.

This is a **heuristic token-counting approximation**, not a true CFG-based cyclomatic complexity. Logical operators (`and`, `or`) and collection operations (`select`, `exists`, `collect`, `iterate`) are not counted. Values should be interpreted as conservative lower bounds.

Inspired by: Götz, Tichy, Kehrer. "Dedicated Model Transformation Languages vs. General-purpose Languages." MODELSWARD 2021.

### n_mm_artifacts — Metamodel Artifact Count

Only ATL has stable per-script values (1 per script, reflecting the single `.xmi` model instance used in testing). ETL / QVTo / Reactions are NaN because per-script artifact counts cannot be derived from the snippet folders alone.

## Correlation Results (`correlation_results.csv`)

Columns: `mtl`, `llm`, `strategy`, `complexity_feature`, `quality_metric`, `spearman_rho`, `p_value`, `n`

- **complexity_feature**: one of `loc`, `n_rules`, `n_helpers`, `n_mm_artifacts`, `mccabe`
- **quality_metric**: one of `chrf`, `unparsed_rate`, `ppls`, `pass_at_1`
- Computed per MTL × LLM × strategy combination
- Rows with `n < 3` or zero-variance series yield `NaN` for ρ and p

# EFinder validator

`efinder_validator` is a separate, headless counterexample backend for any
`.ecore` transformation model generated by ATL2TM. It does **not** convert the
model to `.use` and it does not call the repository's `use_validator` pipeline.

The shipped product embeds the needed Eclipse/EMF/OCL runtime bundles and calls
EFinder, whose solver backend is USE Model Validator. An Eclipse IDE
installation and manually assembled JAR classpaths are therefore not needed.

## How it works

```text
ATL2TM .ecore
  -> copy model and replace selected property P by exists x | not P(x)
  -> headless Equinox product (EMF + Pivot/Complete OCL)
  -> EFinder -> USE Model Validator
  -> SAT: counterexample XMI, UNSAT: no bounded witness
```

The runner reads the property from the standard
`http://www.eclipse.org/emf/2002/Ecore/OCL/Pivot` annotation. The custom
`urn:llm4atl:provenance` annotation is preserved and can help discover/report
checks, but it is not the expression language evaluated by EFinder.

## Layout

```text
runtime/                  Tycho reactor and minimal, pinned target platform
runtime/headless-product/ native headless EFinder product definition
runner/                   OSGi application that prepares, parses and solves a check
efinder_check.py          thin Python wrapper around the packaged launcher
smoke/Person.ecore        reproducible SAT and UNSAT smoke fixture
output/                   generated prepared Ecores, JSON results and SAT XMI
standalone/               legacy plain-Maven experiment; not used by the wrapper
```

The target platform is pinned to the Eclipse **2023-09** release repository and
contains only the runtime bundles required for this product, including Essential
OCL and Complete OCL. It is not the full Eclipse SDK.

## Build the native product

Run this from PowerShell. It needs Java 17+ and Maven; the first build downloads
the pinned p2 bundles and can take longer than later cached builds.

```powershell
Set-Location D:\LLM4ATL\LLM4ATL_neuro_symbolic\efinder_validator\runtime
$target = (Resolve-Path .\target-platform\efinder-headless.target).Path
$env:MAVEN_OPTS = '-Djavax.net.ssl.trustStoreType=Windows-ROOT -Djavax.net.ssl.trustStore=NONE'
mvn.cmd -f pom.xml "-Definder.headless.target=$target" package -DskipTests
```

`MAVEN_OPTS` lets Java trust the Windows certificate store; retain it only when
your Java/Maven HTTPS setup needs it. The produced launcher is:

```text
runtime/headless-product/target/products/org.llm4atl.efinder.headless/
  win32/win32/x86_64/efinder-validator.exe
```

The build uses the EFinder checkout at `../../../third_party/efinder`. Its
parent POM has a small `llm4atl-headless-target` profile so the three upstream
EFinder bundles resolve against this dedicated target only for this build;
normal upstream builds keep their original target platform.

## Run through Python

```powershell
Set-Location D:\LLM4ATL\LLM4ATL_neuro_symbolic\efinder_validator
python .\efinder_check.py .\smoke\Person.ecore `
  --check Person::nonNegative --scope 1 --timeout-ms 30000
```

This returns `SAT` and writes
`output/Person__Person__nonNegative.counterexample.xmi`. The witness has a
`Person` whose `age = -1`, violating `age >= 0`.

The matching bounded UNSAT check is:

```powershell
python .\efinder_check.py .\smoke\Person.ecore `
  --check Person::withinLowerBound --scope 1 --timeout-ms 30000
```

### Minimal Sem/Pre/Post_i formula fixture

`smoke/SemPrePostDemo.ecore` is a tiny ATL2TM-shaped model containing all
three parts of the verification formula:

* `CopySemantics` is `Sem`: `Output.value = Input.value`.
* `source-pre.ocl` is `Pre`: every `Input.value` is `1`.
* `target-post.ocl` contains two selectable `Post_i` properties.

Run both postconditions with the same bounded scope:

```powershell
python .\efinder_check.py .\smoke\SemPrePostDemo.ecore `
  --constraints .\smoke\SemPrePostDemoConstraints `
  --check-all --scope 1 --reference-scope 1 --timeout-ms 30000
```

Expected result: `Output::OutputValueIsOne` is `UNSAT` (the postcondition is
entailed by `Sem AND Pre`), while `Output::OutputValueIsTwo` is `SAT` and its
witness has `Input.value = Output.value = 1`, demonstrating the searched
formula is `Sem AND Pre AND NOT Post_i`.

### Reference-typed target multiplicity counterexample

`smoke/ReferenceTargetMultiplicityViolation.ecore` models an intended target
reference `Task.assignee : Employee [1]`. Its trace semantics creates a `Task`
from a `TicketInput` but deliberately omits the `assignee` binding. The
relaxed target feature is checked by the generated ATL2TM-style postcondition
`targetMultiplicity_Task_assignee`, rather than by a hard Ecore lower bound:

```powershell
python .\efinder_check.py .\smoke\ReferenceTargetMultiplicityViolation.ecore `
  --check Task::targetMultiplicity_Task_assignee --scope 1 --reference-scope 1 `
  --timeout-ms 30000
```

Expected result: `SAT`. The counterexample XMI contains one `CreateTask`, one
`TicketInput`, and one `Task`, but the `Task` has no `assignee` reference.

### Primitive target multiplicities

EFinder/USE cannot soundly represent an ATL target primitive attribute that
was left unbound. Therefore target multiplicities are checked only for
reference-valued features (`EReference`). Target `EAttribute` lower bounds are
still relaxed in the verification Ecore, but their generated `null_*` frame
constraints are removed from the solver premise and no primitive
`targetMultiplicity_*` postcondition is sent to EFinder.

For an explicit primitive multiplicity query, or for one found in an older
ATL2TM model, the wrapper writes `UNSUPPORTED_FEATURE` with an explanation.
`--check-all` includes such entries in its aggregate result; they must not be
interpreted as `UNSAT` proofs. Other supported primitive value constraints
(for example equality or numeric comparisons) remain eligible for EFinder.

## Reproducing `counterexample_demo.use`

The USE demo describes the property
`Employee.manager.oclIsUndefined() or Employee.salary < Employee.manager.salary`
and puts its negation in the `.use` file. The equivalent Ecore fixture stores
the original property as `Employee::P`; the EFinder wrapper then generates the
negation itself, so it is not negated twice:

```powershell
python .\efinder_check.py .\smoke\CounterexampleDemo.ecore `
  --check Employee::P --scope 2 --reference-scope 2 --timeout-ms 30000
```

This produces `SAT` and writes
`output/CounterexampleDemo__Employee__P.counterexample.xmi`. The witness has two
employees and a `manager` link where the employee's salary is not less than the
manager's salary. The Ecore fixture is a faithful conversion of this small demo;
the headless runner does not yet provide a general USE-to-Ecore parser.

The generic command is:

```powershell
python .\efinder_check.py <path-to-atl2tm-model.ecore> `
  --check <EClass>::<constraint-name> `
  --scope 3 --reference-scope 6 --timeout-ms 300000
```

For an ATL2TM model, use `--check-all` to discover every target
`postConstraints` entry and run the intended queries automatically:

```powershell
python .\efinder_check.py <path-to-atl2tm-model.ecore> `
  --check-all --scope 3 --reference-scope 6 --timeout-ms 300000
```

Each query uses `Sem AND Pre AND NOT Post_i`; the aggregate report is written to
`output/<model>.all.result.json`. If the ATL2TM provenance contains no target
postconditions, the command returns `NO_POSTCONSTRAINTS`. Semantic constraints
such as `create_Male` are part of `Sem`, not individual `Post_i` checks.

### External verification profiles

Target invariants may be kept outside the metamodel as one `.ocl` file or a
folder of `.ocl` files. Pass it with `--constraints`; the runner injects every
named `context <EClass> inv <name>:` declaration into the temporary ATL2TM
Ecore copy. Files named `target-post.ocl` (and a single supplied `.ocl` file)
become target `postConstraints`; a `source-pre.ocl` file in the supplied folder
becomes source `preConstraints`. The latter remains enabled in every query,
whereas `--check-all` selects only target posts. Neither the input ATL2TM Ecore
nor the original target metamodel is modified.

For source assumptions that must not be vacuous when no source classifier
exists, `source-pre.ocl` also supports `global inv Name: expression`. The
runner attaches this premise to the selected target context, which is known to
have a witness when checking `NOT Post_i`. If that context is abstract, the
solver instead gives one concrete subclass the minimum scope; the chosen class
is recorded as `bounded_witness_context` in the result JSON.

```powershell
python .\efinder_check.py <path-to-atl2tm-model.ecore> `
  --constraints "..\Neuro-Symbolic Pipeline\pipeline\formal_verification\constraints\Class2Interface_All" `
  --check-all --scope 3 --reference-scope 6
```

The repository's per-case properties are in
`Neuro-Symbolic Pipeline/pipeline/formal_verification/constraints/`.

For every call, the wrapper removes a previous result with the same name before
launching EFinder, so an old witness cannot be reported as a fresh one. Use
`--launcher <path>` to select a product installed in a different location and
`--console-log` to print Equinox diagnostics.

## Run the launcher directly

After building, this bypasses Python while using exactly the same backend:

```powershell
Set-Location D:\LLM4ATL\LLM4ATL_neuro_symbolic\efinder_validator\runtime
.\headless-product\target\products\org.llm4atl.efinder.headless\win32\win32\x86_64\efinder-validator.exe `
  -nosplash --ecore ..\smoke\Person.ecore --check Person::nonNegative `
  --out-dir ..\output --result-json ..\output\direct.result.json `
  --scope 1 --reference-scope 6 --timeout-ms 30000
```

## Result files and statuses

```text
output/<model>__not_<class>__<constraint>.ecore       prepared input model
output/<model>__<class>__<constraint>.result.json    completed run
output/<model>__<class>__<constraint>.counterexample.xmi  SAT only
```

`SAT` is a counterexample within the given bounds. `UNSAT` means no violation
was found within those bounds; it is not an unbounded mathematical proof.
`UNSUPPORTED_FEATURE`, `OCL_PARSE_ERROR`,
`EFINDER_TRANSLATION_ERROR`, `SOLVER_ERROR`, and
`RUNTIME_DEPENDENCY_ERROR` are explicit terminal diagnostics rather than a
fallback to `use_validator`.

For a plain Ecore model without ATL2TM provenance, `--check-all` retains the
older behavior and checks every Ecore constraint independently.

## Unsupported Ecore datatypes

EFinder/USEMV does not support every Ecore datatype (for example `EDate`,
custom `EDataType`s, and some `EEnum`s). Before invoking the solver, the runner
analyses the active `Sem AND Pre AND NOT Post_i` formula. If an unsupported
attribute occurs only in an ATL2TM-generated `null_*` frame constraint, the
**prepared Ecore copy** maps that attribute to `EString` and removes that
now-irrelevant frame constraint. The same treatment applies to any datatype
outside the runner's supported primitive set (`EString`, `EBoolean`, numeric
Ecore primitives).
The original ATL2TM Ecore is not changed; the JSON result records the change
in `abstracted_features`.

If the unsupported attribute is read by an active semantic constraint,
precondition, selected postcondition, guard, or binding encoding, the runner
does not abstract it. It returns `UNSUPPORTED_FEATURE` before solving and
names the dependent constraints in `detail`. Supporting that case requires a
sound finite encoding in the EFinder backend (for example, dates as bounded
integers), rather than silently dropping information.
